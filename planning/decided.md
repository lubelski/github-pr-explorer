# Decided

What is settled for github-pr-explorer. [PLAN.md](../PLAN.md) has what is being worked on and what is still open. [ideas.md](ideas.md) has ideas.

- The name is `github-pr-explorer`
  - The repo, the folder, and later the app and bundle all use it in full.
- It is a native Mac app
  - Swift, for the current macOS only. The owner asked for "fully native".
- It starts fresh
  - `github-pr-watch-menubar` is an earlier app on a related problem. The owner said on 2026-11-25 to set that work aside and not build on it. Nothing here depends on it.
- Design comes before code
  - The owner asked for ideas to be tried in Figma before anything is built. He reacted to the first rows on 2026-11-25, so building has started. He has not yet chosen between rows.
- Build on mock data first
  - The owner asked on 2026-11-25 for lots of mock data, to help work on the app and to get building started before sync exists.
  - The mock data is the same placeholder world the Figma rows use: the org `acme`, its repos and people, and pull request `acme/api #4826` as the worked example.
- The model is plain values in one core library
  - `GitHubPRExplorerCore` holds the models, the logic derived from them, the index protocol, and the mock world. It uses Foundation only and has no network code.
  - Every type is a `Codable`, `Sendable`, `Hashable` value. A `PullRequest` holds every section in one value: metadata and merge state, reviews and code owners, checks, files and commits, threads, and conversation comments and the timeline.
  - Each of those six sections carries its own `SectionProvenance`: a source (GraphQL API, REST API, local clone, push, web page, mock) and when it was fetched. Code owners count as reviews, commits as files, and conversation comments as timeline.
  - A file keeps its patch as GitHub's per-file text, hunks only. The parsed form, with old and new line numbers, is worked out on demand by `PatchParser` and is not stored.
  - A review request is pending by definition, because GitHub drops it once that reviewer reviews.
  - A thread on a removed line points at the old file (`side: left`), so the quoted line can always be found in the patch.
  - The index protocol is small and synchronous: all pull requests, one by id or by reference, the viewer, and a word search over title, number, author, repository and file paths. Each word must appear somewhere, ignoring case and accents. It is not the filter language.
- The mock world is fixed and deterministic
  - `MockWorld.standard` is seen from a fixed `now`, 2026-11-25T18:00:00Z. Two builds encode to byte-identical JSON, and a test checks it.
  - Randomness comes from a SplitMix64 generator written in the package, seeded per pull request from its reference, so adding one pull request never changes another. The standard library's random functions are never used, since their algorithms may change between Swift releases.
  - It holds the org `acme`, its repos `api`, `web`, `infra` and `docs`, 8 people who do most of the work, 22 who review now and then (so one pull request can ask 30 reviewers), three bots, and two agents with obviously placeholder logins (`example-agent-one`, `example-agent-two`). The viewer is Robin Quill (`robin-quill`), on `@acme/security`. The second team is `@acme/web-platform`.
  - It has exactly 218 open, 60 merged and 20 closed pull requests. `acme/api #4826` is written by hand to match the designs, and so are the 14 others the designs name. The rest are built from parts, with every status state in every repository, and the awkward cases views need: a 120-file pull request with a 5,000-line patch, a 287-event timeline, ci-bot's expensive-CI checkbox, empty and rich bodies, a very long title, non-ASCII text, 30 reviewers and none, 40 checks and none, renamed, removed, added and binary files, and outdated and resolved threads.
  - Its provenance uses the sources a real sync would use, with varied ages and some stale, so freshness views have something to show. `mock` is kept for data made up by a test or a preview.
  - When a view needs a case the world lacks, add it to the world in the same pull request.
- The status sentence has one precedence
  - A pull request's state is a symbol and one plain sentence, with every reason found. The first match wins: merged `✓`, closed `⊘`, draft `○`, in the merge queue `●`, blocked `✕` (merge conflicts or a failed required check, listing changes requested and unresolved threads too), changes requested `✕`, CI running `●`, checks queued `●`, a check that is not required failed `◐`, threads unresolved `◐`, waiting on reviewers or needs a review `◐`, behind the base branch `◐`, checking for conflicts `◐`, ready to merge `✓`.
  - Outdated threads that are not resolved count as unresolved, as GitHub's conversation rule counts them.
  - When a review is asked of the viewer or one of the viewer's teams, the sentence ends "Review requested from you." The comment on `StatusSentence` is the full rule.
- The command line tool starts with the mock world
  - `github-pr-explorer-ctl` lists pull requests, shows one, and exports the mock world. `list` prints tab-separated lines so agents can split them. `show --json` prints the same JSON the export writes.
  - The export writes `world.json` and one file per pull request under `pull-requests/`, named like `acme-api-4826.json`.
- A page layout is a JSON document
  - `PageLayout` has a format version, an id, a name, and tabs in order. A tab has a name and columns in order. A column has a relative width and blocks in order. A block placement is a block kind and a size, small or large. It is `Codable` and written with sorted keys, so the same layout is the same bytes.
  - The block kinds are description, checks, reviewers, owners touched, files, threads, activity, commits, and labels and metadata. An unknown kind fails to decode. A tab with no blocks is allowed.
  - A file that does not decode is reported with its file name, where in the file, and what is wrong, such as `decision-first.json, at tabs[0].columns[0].blocks[0].kind: unknown block kind "summary"`. The app shows the problem in the title bar and keeps going. When "Decision first" itself cannot be read, a copy compiled into the app is used, and a test keeps the two equal.
  - Layout rules, a configuration folder, and Edit Layout come later and build on this shape.
- Two layouts ship
  - "Decision first", after Figma row 1: one tab, two columns at widths 1.85 and 1. Left: Description, Threads, Files. Right: Checks, Reviewers, Owners touched, Activity.
  - "Tabbed", after Figma row 2: Overview (Description, Reviewers, Owners touched, Activity), Files (Files, Commits), Checks, Threads.
  - Both are JSON resource files in the core library, read through the same decoding a person's own file goes through. The layout menu at the right end of the title bar switches between them.
- The header is fixed above the tabs, for now
  - The repository and number, title, status sentence, and action buttons sit above the tabs and are not a block. This is temporary. `VISION.md` says no block has a fixed place, so the header becomes a block, or blocks, when Edit Layout arrives.
  - The action buttons are disabled with the tooltip "Not connected to GitHub yet". The line under them says why Merge is unavailable when it is.
- The page reads a fixed clock
  - The window measures every age from `MockWorld.now`, so it reads the same on every run. Freshness at the right end of the title bar is the oldest section's age, so it never claims more than is true, and its tooltip lists each section with its source.
- The main window has no footer, and status sits in the title bar (MAC-55)
  - The app's name is drawn once, centered. The system's own title is hidden with SwiftUI's `.toolbar(removing: .title)`, and the title bar helper hides it again if anything turns it back on, because SwiftUI can reset it on a `Window` scene's window after the helper last ran. Renders use a plain `NSWindow`, so they never showed the second title.
  - The right end of the title bar holds, right-aligned in quiet secondary text: the selected pull request's freshness (its tooltip lists each section's age and source), a warning when a layout file could not be read, the version, build and commit as `bundle.sh` stamps them ("0.1 (4) · b41c422"), and last a small menu that shows the current layout's name and lists the layouts. The update indicator goes between the version and the layout menu when MAC-47 adds the updater. Renders show a fixed "0.1 (0) · preview" so they read the same at every commit.
  - The layout menu is in the title bar for now. Edit Layout and layout rules may move it.
- The list has three fixed views (MAC-55)
  - "Needs my review": open pull requests where a review is asked of the viewer or one of the viewer's teams, never the viewer's own. "Mine": open pull requests the viewer wrote. "Everything open": every open pull request. Each shows its count within the search, and the search narrows within the chosen view.
  - They are plain predicates in the core library (`FixedListView`), not the filter language and not saved views. When the filter language arrives they become built-in filters written in it, and the type goes away rather than becoming a second way to write a condition.
  - The list starts in "Needs my review", because the vision is about deciding on pull requests and that view is the ones waiting on the viewer. The worked example, `acme/api #4826`, is in it. In the mock world the counts are 48, 12 and 218.
  - Changing the view keeps the open page, even when that pull request is not in the new view.
  - When the list is too narrow for the full names, the row uses short ones: "Review", "Mine", "All open".
- The list's width follows a drag on its trailing edge (MAC-55)
  - From 260 to 480 points, 300 by default. Double-clicking the edge puts it back to 300. In a small window the list gives way so the page keeps at least 600 points, without forgetting the width chosen.
- Window state is not configuration (MAC-55)
  - The list's width and the chosen view are remembered across launches in `UserDefaults`, as window state: where the person left the window. They are not settings, so they are not files in the configuration folder and not reachable from the command line or MCP. Anything that changes what the app does still belongs in the configuration folder.
- Renders are drawn offscreen
  - `github-pr-explorer --render-previews <folder> [state ...]` builds the real window with the mock world's index and a model set to each named state, in a titled window that is never put on screen, and writes a PNG in light and in dark. It sets the activation policy to prohibited, so nothing appears and nothing takes focus. `scripts/render-previews.sh` runs it, stamped and signed as the bundle is, and can attach the PNGs to a pull request.
  - The states cover #4826 in each layout and tab, the awkward mock cases, the list with a search, each list view, the list at its narrowest and widest, the smallest window, a bad layout file, and every block at both sizes, full and empty. The empty one is made up in the renderer with provenance `mock`.
  - Offscreen, a list's selected row does not draw, so the list draws it by hand while rendering.
- Pull requests are merged by whoever wrote them
  - The owner said on 2026-11-25 that sessions and their subagents may merge as they work, because the app has no users until he installs it.
- The vision and the plan are separate files
  - `VISION.md` holds what does not change. `PLAN.md` holds what does. The owner asked for this split.
